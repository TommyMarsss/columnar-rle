# columnar-rle

列式存储的 RLE（Run-Length Encoding）压缩与谓词下推查询。仅使用 Go 标准库，不依赖任何第三方列存/压缩库。

## 模块结构

| 文件 | 职责 |
|---|---|
| `rle.go` | RLE 编码/解码，超长 run 的分段 |
| `predicate.go` | 等值/范围谓词，块级三分判定（SKIP / ALL / PARTIAL） |
| `column.go` | 分块列存、谓词下推过滤、跨块聚合（COUNT/SUM） |
| `cmd/sitegen` | 生成单文件静态 HTML 演示页（`rle_demo.html`） |

## RLE 编码格式

一列 `[]int64` 先按固定行数切分为若干 **块（Block）**（默认 1024 行/块，最后一块可不足），每块独立编码为 run 序列：

```
Run = (Value int64, Count uint16 逻辑宽度)
```

- 相邻相同值合并为一个 `(值, 重复次数)` 对；
- **分段阈值**：计数字段按 16 位设计，单段上限 `MaxRunCount = 65535`。当一个逻辑 run 的长度超过上限时，编码器将其切分为 `⌊n / 65535⌋` 个满段加一个余数段，例如 42 重复 131077 次 → `(42, 65535), (42, 65535), (42, 7)`。绝不溢出或截断计数；
- 选择 65535 作为阈值的理由：16 位计数在存储开销（每 run 仅 2 字节计数）与分段频率之间取得平衡——绝大多数真实列的 run 远短于 6 万行，分段几乎不发生；即使发生，代价也只是多几个 run，且解码语义完全不变。阈值集中定义为常量 `MaxRunCount`，需要更宽计数（如 32 位）时只改这一处；
- 每个块额外维护 **min / max / sum / 行数** 统计，供谓词下推与聚合下推使用；
- 不变式：`Decode(Encode(v)) == v` 对任意输入成立（含空列、单元素、全相同、全不同），测试中有随机数据往返验证。

## 谓词下推决策规则

谓词为闭区间 `[Lo, Hi]`（等值谓词即 `Lo == Hi`）。对每个块只用 min/max 统计做三分判定，**不读取块内实际值**：

| 条件 | 判定 | 动作 |
|---|---|---|
| `Lo ≤ min 且 max ≤ Hi` | `ALL` | 整块接受：过滤直接计入全部行号；聚合直接累加块级 `Rows`/`Sum`，不解压 |
| `max < Lo 或 min > Hi` | `SKIP` | 整块跳过：不可能含命中行，不解压 |
| 其他（区间与 [min,max] 部分相交） | `PARTIAL` | 解压该块，逐行判断 |

正确性论证：块的 min/max 是该块值的紧界，因此

- **不漏结果**：`SKIP` 当且仅当块内所有值都在谓词区间之外，跳过绝不会丢失命中行；
- **不多跳过**：判定规则是按 min/max 可判定的充要条件，凡规则允许跳过的块都被跳过（测试用独立重算的 min/max 逐块核对跳过/接受/展开数量，既验证"不多跳"也验证"不少跳"）；
- 注意 min/max 是保守估计：`PARTIAL` 块展开后可能实际零命中（例如块含 1 和 10 但谓词是 `= 5`）。这是 zone-map 的固有性质，不影响结果正确性。

## 跨块边界聚合

`Column.Aggregate(p)` 计算满足谓词行的 `COUNT(*)` 与 `SUM(value)`：

- `ALL` 块：直接累加预计算的 `Rows` 与 `Sum`，完全不解压；
- `SKIP` 块：跳过；
- `PARTIAL` 块：解压后逐行判断再累加。

查询区间在某个块中间切开时，该块必然落入 `PARTIAL`（区间不可能完整覆盖它的 [min,max]，除非区间端点恰在块外），逐行判断保证切开处不多算、不少算。测试用暴力全展开结果对一批等值/范围谓词（含切中块中间的区间）逐一比对 COUNT/SUM 与命中行号集合。

## 运行

```bash
go test ./...          # 全部自动化测试
go run ./cmd/sitegen   # 生成 rle_demo.html（默认输出名，可用 -out 指定）
```

`rle_demo.html` 是单一静态文件：数据与渲染逻辑全部内嵌，无服务器、无第三方库、无外部请求。浏览器打开后可查看：

1. 原始列数据（按块着色）；
2. 每个块的 RLE run 序列与 min/max/sum 统计；
3. 超长 run 的分段编码示例；
4. 每组谓词查询下每个块被 SKIP / ALL / PARTIAL 的决策过程，展开块的逐行命中行号，以及聚合结果与浏览器端暴力全展开复核的一致性校验。

## 测试覆盖

- `rle_test.go`：空列/单元素/全相同/全不同/交替/负值等边界的编解码往返；`MaxRunCount±1`、`2×MaxRunCount+7` 等分段边界；分段不与异值 run 错误合并；200 组随机数据往返。
- `predicate_test.go`：块级三分判定的边界（区间端点恰触 min/max、负值、交换界归一化）。
- `column_test.go`：列往返（含最后一块不足）；过滤结果与暴力全展开逐行比对；跳过/接受/展开块数与独立重算的期望值精确一致；跳过块零命中、整块接受块全命中的 soundness 校验；跨块边界聚合（区间切中块中间）与全展开聚合一致；分段长 run 所在块的聚合正确性。
